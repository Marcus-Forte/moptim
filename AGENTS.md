# Moptim

C++23 non-linear least-squares library (Gauss-Newton, Levenberg-Marquardt) on Eigen, for the host CPU. The partitions of large costs run on oneTBB (`MOPTIM_WITH_TBB`, default ON), everything else on the calling thread. See `README.md` for the math, dimension conventions and user-facing behaviour.

## Build / test
- Plain C++ with any compiler (the `default` preset: GCC via `/opt/toolchain/gcc.cmake`, Ninja, `build/`). Only `-Wall` is set (no `-Werror`); the build adds no other flags and no `-ffp-contract` setting. `-DFORMAT_CODE=ON` runs clang-format -i over all `.cc`/`.hh` on build; `-DUSE_CLANG_TIDY=ON` runs clang-tidy.
- oneTBB: `option(MOPTIM_WITH_TBB ON)`; `find_package(TBB)` (skipped when a parent project already has a `TBB::tbb` target), then `target_link_libraries(moptim PRIVATE TBB::tbb)` and a PRIVATE `MOPTIM_HAS_TBB=1`. Not found: a `message(WARNING)` and a sequential build (`ExecutionContext::parallelAvailable()` is false). No public header may include or name TBB.
- Build in a scratch directory, **not** the repo's `build/` (it can hold the user's IDE build): `cmake --preset default -B <dir>` or `cmake -S . -B <dir> -G Ninja -DCMAKE_BUILD_TYPE=Release`, then `cmake --build <dir> -j 6` and `ctest --test-dir <dir> --output-on-failure -j 6`. Eigen and oneTBB come from the system (Debian/Ubuntu: `libeigen3-dev`, `libtbb-dev`).
- Tests: gtest (FetchContent at configure time, needs network); binary `test_moptim`, one test with `--gtest_filter=Suite.Name`. 170 tests on 2026-11-25 (with oneTBB; the assertions about several threads skip without it). `test_host_backend.cc` covers the `ExecutionContext` (thread counts, arena, exceptions, the `launches()` count); `test_determinism.cc` the bitwise independence of the thread count. For races run `Determinism*:ExecutionContextTest*:*CostModels*:FusedCost*:AsyncCost*` in a ThreadSanitizer build (`-DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_CXX_FLAGS=-fsanitize=thread -DCMAKE_EXE_LINKER_FLAGS=-fsanitize=thread`); reports from inside TBB's own code can be false positives (TBB's synchronization is not instrumented without its own TSan support).
- Benchmarks: `<build>/test/bench_moptim [--threads N] [--speculative] [name-substring]` (first line: `threads=<resolved> tbb=<on|off>`; not run by ctest; prints cost/`JTJ`/`JTb` checksums). Compare two runs or builds with `test/compare_bench.py` (per-key differences; zero tolerances between thread counts; `--tol-numerical` for forward/central rows across compilers). Timings are noisy: compare minima over interleaved runs.

## Layout
- `include/moptim/*.hh`: header templates (costs, models, observer, result); consumers include `"moptim/<Header>.hh"`. **Public headers must stay valid C++20** (mslam consumes them as a C++20 submodule). `src/` has `EigenSolver.cc`, `ExecutionContext.cc`, `GaussNewton.cc`, `LevenbergMarquardt.cc`, `NormalEquations.cc`; all but `ExecutionContext.cc` use explicit instantiation (a new scalar type means editing them).
- `ExecutionContext` (`ExecutionContext.hh`, `src/ExecutionContext.cc`): `threads()` (0 = all hardware threads), `resolvedThreads()`, `launchWidth(partitions, LaunchWork)` = 1 below `kMinPartitionsToGoWide` (6, linear system) / `kMinPartitionsToGoWideCostOnly` (12, cost-only evaluations), else `min(resolvedThreads(), ceil(partitions / 2))` (always 1 without TBB; the constants are where threads 0 stopped being slower than threads 1 in a sweep, so re-measure before changing them; width never changes bits), `parallelAvailable()`, `launches()` (the number of evaluations dispatched through the context), `runOnHost(tasks, fn, data)` and `defaultContext()`. A pimpl `detail::HostExecutor` (defined in the .cc, held by `unique_ptr`) owns a `tbb::task_arena` with max concurrency = `resolvedThreads()`, created in the constructor and re-created by `setThreads()` (never lazily: the old pool's lazy creation was racy). `runOnHost` runs one task inline, else `arena.execute` + `tbb::parallel_for` with grain 1 (simple partitioner: one task per worker); a worker's exception reaches the caller. `detail::submit(context, tasks, fn(size_t task))` counts one evaluation and runs the tasks, one per worker; `detail::runOnCallingThread` is a counted evaluation on the calling thread.
- Costs: `ChunkedCost<Model,T,Policy>` (`ChunkedCost.hh`) is the orchestration (models, `x`, scratch, partials as aligned heap arrays (`detail/AlignedArray.hh`) allocated on first use; the loss descriptor read at every call; one evaluation per call, nothing dispatched for zero elements; reduction of the partials). `launch()` (starts an evaluation): width 1 (or a `stepped()` cost) takes `runInline`, wider takes `detail::submit` with the claim loop on an `std::atomic_ref` counter. `AnalyticalCost` and `NumericalCost` (aliases `NumericalCostForwardEuler`/`Central`) only supply a compile-time Jacobian policy (`detail::AnalyticalJacobian`, `detail::NumericalJacobian`). `ICost` stays a virtual interface that users subclass.
- `include/moptim/detail/`: `ChunkKernel.hh` (the per-worker chunk loop `runWorkItem`, `robustifyChunk`, `KernelArgs`; Eigen-free), `Partitioning.hh` (chunk and partition arithmetic), `NormalEquationsKernel.hh` (fused accumulation routines, wrapped by `src/NormalEquations.cc`), `AlignedArray.hh` (aligned heap RAII).
- Numerical costs keep `1 + kP*P_active` models (copy-constructed once; `setState` on each with its point before every linear-system evaluation; none for a const-callable model whose elements fit in one chunk, which `stepped()` walks with one model); the point table is filled on the calling thread (Euclidean: `x[p] ± h`; manifold: `plus(x, ±h e_p)`).
- Async API: `ICost::submitLinearSystem/submitCost/wait` default to the synchronous calls. `ChunkedCost` submits (the evaluation runs inside the call) and `wait()` reduces into the remembered outputs; any call on a cost with a pending evaluation waits first (destructor and `setWeights/setInformation/setLossFunction` too). `IOptimizer` keeps one `CostWorkspace` per cost (sized in `addCost`), submits all, waits all, sums in cost order.
- `FusedCost<T, Costs...>` (`FusedCost.hh`, `makeFusedCost<T>()`): several `ChunkedCost`s evaluated in one dispatch. Each sub-cost keeps its partitions, partials, claim counter and scratch (`ChunkedCost::prepareFused/runFused/finishFused`, a friend interface; `prepare()` and `reduce()` are shared with the normal evaluation), so results equal the separate costs bitwise and the fused sum is in cost order. Number of threads = the widest sub-cost's. Tests: `test/test_fused_cost.cc`.
- `ChunkedCost::setData(input, obs, n)` / `setModel(model)`: reuse a cost with new elements or a new model (partitioning and slice layout recomputed, partials/scratch grown only when needed, models rebuilt in place). `setData()` drops weights/information. `ICost::num_elements_` is therefore not const.
- `LevenbergMarquardt::setSpeculativeLinearSystems(true)`: trials use `assembleLinearSystemInto` (own buffers, swapped in on acceptance); `onLinearSystem` fires only for used systems. Tests: `test/test_async.cc`.
- Models are called from several threads when a cost uses several threads (rules in `IModel.hh` and README "Models"): moved into the cost's storage, used in place when const-callable, else per-worker copies, else one worker. Never memcpy a model. Only built-in losses (`setLossFunction` throws for `LossKind::Custom`); custom losses could come back now that nothing needs a descriptor that can be copied to another memory space, but they would have to be const and thread-safe.
- `test/`: gtest suites; new files must be added to `test/CMakeLists.txt`. `test/nist/` holds the NIST StRD datasets (one executable; together with `test_tu_models*.cc`, whose anonymous-namespace models have the same name in two files, it checks that same-named models do not get mixed up). `test/manifold_models.hh` has the test/bench manifolds and models.
- Library has no logging or timing: telemetry goes through `IOptimizerObserver` (`Observer.hh`). No `<iostream>`, `<format>` or logger dependencies (see `docs/logging.md`).
- `Manifold.hh` (`IManifold`, `EuclideanManifold`, `ProductManifold`) is a runtime interface (not a template parameter: the optimizers are explicitly instantiated). No geometry (SO(3)/SE(3)) in the library. A model's `jacobian` is the derivative with respect to the step at zero, `active_param_dim` counts tangent dimensions, and an optimizer and its costs are all built from plain dimensions or all from the same manifold object (`addCost` checks it).

## Invariants to preserve
- **Bitwise determinism across thread counts**, run to run. Partition boundaries (`detail/Partitioning.hh` and its constants) and the order of the reduction (`ChunkedCost::reducePartials`, partition order; `FusedCost`, cost order) are fixed and must never depend on the thread count, the number of workers or the scheduling: workers only decide who computes a partition, each partition writes its own slot. Do not add a reduction over workers, per-thread accumulators or `tbb::parallel_reduce`.
- **TBB only in `src/`, linked PRIVATE.** No public header (and nothing under `include/`) includes or names TBB; `ExecutionContext` reaches it through the forward-declared `detail::HostExecutor`. The build has no `MOPTIM_HAS_TBB` outside moptim's own sources, and the code must build and give the same results without TBB.
- **Public headers stay valid C++20** (the library itself is C++23), and add no compiler flags for consumers: the target passes on only the include path and Eigen.
- **Euclidean == `EuclideanManifold` bitwise** (same arithmetic, no extra work in hot loops).
- **Linear-system cost == `computeCost(x)` bitwise** (both go through the same `robustifyChunk`/`robustifyElement` and the same partitions); speculative LM relies on it.
- **One dispatch per evaluation** (`context.launches()` goes up by one), none for zero elements; a `FusedCost` evaluation is one dispatch.
- **The arena is created in the constructor and in `setThreads()`, never lazily.**
- No exceptions thrown by the library's own per-worker code; model exceptions propagate through `runOnHost`.
- Check changes with `Determinism*` (also under ThreadSanitizer) and `compare_bench.py` against a build of the previous tree and between `--threads 1` and `--threads 0`: analytical and numerical rows must match exactly on the same compiler (`--tol 0 --tol-numerical 0`).
