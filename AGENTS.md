# Moptim

C++23 non-linear least-squares library (Gauss-Newton, Levenberg-Marquardt) on Eigen, with an opt-in SYCL backend (`MOPTIM_WITH_SYCL`, default OFF). See `README.md` for the math, dimension conventions and user-facing behaviour.

## Build / test
- SYCL is opt-in: `MOPTIM_WITH_SYCL=OFF` (default) is plain C++ with any compiler (the `default` preset: GCC via `/opt/toolchain/gcc.cmake`) and only the host backend; `ON` needs the DPC++ `clang++` (`-fsycl`) and defines `MOPTIM_HAS_SYCL=1` PUBLIC. One implementation, two launchers: `ExecutionContext` has a `Backend` (`Host` always, `Sycl` with SYCL; `defaultBackend()` = `MOPTIM_BACKEND=host|sycl`, else Sycl when built with it); costs allocate through the context (`detail::makeSharedArray(context, ...)`) and launch through `detail::submitNamed<Name>(context, groups, kernel)`, where `kernel(size_t group)` runs as a SYCL nd_range kernel or on the host (in order on the calling thread: the host backend is the sequential reference and has no threads, parallelism comes only from SYCL; `launchWidth()` is 1 on the host and `threads` only applies to the SYCL backend). Kernel bodies use `moptim/Atomic.hh` (sycl::atomic_ref in a device pass, std::atomic_ref otherwise). The WorkGroup kernel, the model layout check and kernel names (`CurrentTuId`) are SYCL-only. Any code reachable from a `submitNamed` kernel must be device code in a SYCL build even when it only runs on the host backend (it is compiled for the device too). With SYCL, Eigen settings (README "Eigen in the device pass"): scalar Eigen in the device pass only (`EIGEN_DONT_VECTORIZE` through `-Xsycl-target-frontend=<triple>` in `CMakeLists.txt`, never in a header or as a global define), `EIGEN_MAX_STATIC_ALIGN_BYTES=16` on both passes, `-ffp-contract=on` (`MOPTIM_FP_CONTRACT`; `fast` fuses differently per inlining context and broke the bitwise cost invariant with Eigen 5; benchmark reference outputs from builds before this change differ in the last bits). The `native_cpu` device pass also gets `-U__ARM_NEON -U__ARM_NEON__` (same `-Xsycl-target-frontend`, `PUBLIC`): it crashes on `<arm_neon.h>`, which OpenCV's and abseil's headers include under `__ARM_NEON`; including `<arm_neon.h>` directly in a SYCL TU still crashes this compiler. It also gets `-U__ARM_FEATURE_FP16_SCALAR_ARITHMETIC -U__ARM_FEATURE_FP16_VECTOR_ARITHMETIC`: with a CPU that has FP16 arithmetic (`-mcpu=cortex-a76`, mslam's `pi5` preset) Eigen 5 stores `Eigen::half` as `__fp16`, which the device front end rejects as a parameter type. Do not re-add a global `EIGEN_DONT_VECTORIZE` or `EIGEN_ARM64_USE_SVE`.
- Presets: `cmake --preset default` (host only, GCC, `build/`), `--preset sycl-cpu` (DPC++ at `/opt/sycl`, `native_cpu`, `build_sycl_cpu/`) and `--preset sycl` (`native_cpu,nvptx64-nvidia-cuda,spir64`, `build_sycl/`, needs the CUDA and libspirv bitcode). Variables: `MOPTIM_WITH_SYCL`, `SYCL_TARGETS`, `MOPTIM_NATIVE_CPU_ARCH`, `MOPTIM_FP_CONTRACT`.
- The macOS host has no SYCL compiler. Build in the dev container: `C=$(docker ps -q --filter ancestor=mdnf1992/cpp-dev)`; repo at `/workspaces/moptim`, DPC++ at `/opt/sycl`, Eigen in `/usr/include/eigen3`, only the `native_cpu` device. Use a container-local build dir (`/root/moptim-builds/<name>`), **never** the repo's `build/`, `build_sycl/` or `build_sycl_cpu/`: each has its own devcontainer volume that holds the user's IDE build, so building there clobbers it.
  `docker exec $C cmake -S /workspaces/moptim -B /root/moptim-builds/<name> -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=/opt/sycl/bin/clang -DCMAKE_CXX_COMPILER=/opt/sycl/bin/clang++`, then `docker exec $C cmake --build /root/moptim-builds/<name> -j 8` and `docker exec $C ctest --test-dir /root/moptim-builds/<name> --output-on-failure -j 4`.
- Tests: gtest (FetchContent at configure time, needs network); binary `test_moptim`, one test with `--gtest_filter=Suite.Name`. Build and test both configurations: host-only (168 tests on 2026-11-22) and SYCL, where ctest runs the suite on both backends (the `*.host` copies run with `MOPTIM_BACKEND=host`; 403 tests). `test_host_backend.cc` covers the host launcher; SYCL-only tests (`test_execution_context`, `test_device_*`, `test_workgroup`, `bench_launch`) only build with SYCL. Also run `Determinism*:*CostModels*:WorkGroup*:AsyncCost*:SpeculativeLM*` under `SYCL_NATIVE_CPU_HOST_THREADS=1` and `=4`.
- Benchmarks: `<build>/test/bench_moptim [--backend host|sycl] [--threads N (SYCL only)] [--strategy auto|chunked|workgroup] [--speculative] [name-substring]` (first line: the backend) (not run by ctest; prints cost/`JTJ`/`JTb` checksums). Compare two builds with `test/compare_bench.py` (per-key differences; `--tol-numerical` for forward/central rows). Timings are noisy: compare minima over interleaved runs. `test/bench_launch.cc` measures launch latency.
- Only `-Wall` is set (no `-Werror`). clang-tidy cannot parse a `-fsycl` compilation (`-DUSE_CLANG_TIDY=ON` only warns). `-DFORMAT_CODE=ON` runs clang-format -i over all `.cc`/`.hh` on build.

## Layout
- `include/moptim/*.hh`: header templates (costs, models, observer, result); consumers include `"moptim/<Header>.hh"`. **Public headers must stay valid C++20** (mslam consumes them as a C++20 submodule). `src/` has `EigenSolver.cc`, `ExecutionContext.cc`, `GaussNewton.cc`, `LevenbergMarquardt.cc`, `NormalEquations.cc`; all but `ExecutionContext.cc` use explicit instantiation (a new scalar type means editing them).
- Costs: `ChunkedCost<Model,T,Policy>` (`ChunkedCost.hh`) is the host orchestration (models, `x`, scratch, partials in USM allocated on first use; the loss descriptor read at every call; one launch per evaluation, none for zero elements; reduction of the partials). `AnalyticalCost` and `NumericalCost` (aliases `NumericalCostForwardEuler`/`Central`) only supply a compile-time Jacobian policy (`detail::AnalyticalJacobian`, `detail::NumericalJacobian`); no virtual calls in device paths. `ICost` stays a virtual host interface that users subclass.
- `include/moptim/detail/`: `ChunkKernel.hh` (Chunked device code: `runWorkItem`, `robustifyChunk`, `KernelArgs`; Eigen-free, host-callable), `Partitioning.hh` (chunk and partition arithmetic), `WorkGroupKernel.hh` (WorkGroup device code), `NormalEquationsKernel.hh` (fused accumulation kernels, wrapped by `src/NormalEquations.cc`), `KernelName.hh` (TU-unique kernel names), `Usm.hh` (USM RAII). `ExecutionContext.hh` has the queue, `threads`, `AssemblyStrategy`, work-group size, launch counter and `detail::submitNamed/launchNamed/submitWithLocalMemory/complete`.
- Numerical costs keep `1 + kP*P_active` models in USM (copy-constructed once; `setState` on each with its point on the host before every linear-system launch); the point table is filled on the host (Euclidean: `x[p] ± h`; manifold: `plus(x, ±h e_p)`).
- Async API: `ICost::submitLinearSystem/submitCost/wait` default to the synchronous calls. `ChunkedCost` submits without waiting; `wait()` completes and reduces into the remembered outputs; any call on a cost with a pending evaluation waits first (destructor and `setWeights/setInformation/setLossFunction` too). `IOptimizer` keeps one `CostWorkspace` per cost (sized in `addCost`), submits all, waits all, sums in cost order. On native_cpu a submit runs the kernel inside the call, so nothing overlaps.
- `FusedCost<T, Costs...>` (`FusedCost.hh`, `makeFusedCost<T>()`): several `ChunkedCost`s in one chunked kernel. Each sub-cost keeps its partitions, partials, claim counter and scratch (`ChunkedCost::prepareFused/runFused/finishFused`, a friend interface; `prepare()` and `reduce()` are shared with the normal launch), so results equal the separate costs bitwise and the fused sum is in cost order (`IOptimizer` adds 0 + fused = the same bits). The kernel is named after the sub-costs' policies (`FusedKernelName<kLS, T, TuId, Policies...>`): a kernel name cannot mention the constrained cost templates (the integration header would need the concepts). Any sub-cost on the WorkGroup kernel makes the fused cost launch them one by one. Tests: `test/test_fused_cost.cc`.
- `DeviceLevenbergMarquardt<T, Manifold, Costs...>` (`DeviceLevenbergMarquardt.hh`): the whole LM (speculative) in one `single_task`: `ChunkedCost::prepareLoop()` (host: buffers for one work-item, kernel args) and `loopEvaluate<Manifold, kLS>()` (device: sets `x_`, the model states and a numerical policy's points with `Manifold::plus`, runs the partitions in order through `runWorkItem`, reduces with `reducePartials()`, which the host `reduce()` shares). `Manifold` is a compile-time `DeviceManifold` (`EuclideanSpace<T, N>` provided); models' `setState()` must be device code. Results follow the host LM up to rounding (own Cholesky, scalar Eigen), same iterations/status in `test/test_device_lm.cc`. Kernel named `DeviceLMKernelName<T, Manifold, TuId, Policies...>`; counted as one launch.
- `ChunkedCost::setData(input, obs, n)` / `setModel(model)`: reuse a cost with new elements or a new model (partitioning and slice layout recomputed, partials/scratch grown only when needed, models rebuilt in place in their USM storage). `setData()` drops weights/information. `ICost::num_elements_` is therefore not const.
- `LevenbergMarquardt::setSpeculativeLinearSystems(true)`: trials use `assembleLinearSystemInto` (own buffers, swapped in on acceptance); `onLinearSystem` fires only for used systems. Tests: `test/test_async.cc`.
- Models are device code (rules in `IModel.hh` and README "Models"): move-constructed into USM, used in place when const-callable, else per-work-item copies (Chunked) or Chunked fallback (WorkGroup). Never memcpy a model or capture one by value in a kernel. Only built-in losses (`setLossFunction` throws for `LossKind::Custom`). `std::sin/exp/log` in a model work on native_cpu but make the DPC++ link warn; library math goes through `sycl::` helpers under `__SYCL_DEVICE_ONLY__` (`LossFunction.hh`).
- With GCC >= 16 libstdc++, DPC++ rejects `std::copy`/`std::distance`/`std::ranges` algorithms on iterators in device code (false positive on `default_initializable`'s `::new`) and `std::sort` (recursion): use loops or `__builtin_memcpy`; `std::fill`, `std::min`/`std::max`, `std::array` and `std::swap` are fine.
- `test/`: gtest suites; new files must be added to `test/CMakeLists.txt`. `test/nist/` holds the NIST StRD datasets (one executable, which is the same-name-kernel regression test together with `test_tu_models*.cc`). `test_device_*.cc` and `test_execution_context.cc` run kernels on the default device and compare with the host. `test/manifold_models.hh` has the test/bench manifolds and models.
- Library has no logging or timing: telemetry goes through `IOptimizerObserver` (`Observer.hh`). No `<iostream>`, `<format>` or logger dependencies (see `docs/logging.md`).
- `Manifold.hh` (`IManifold`, `EuclideanManifold`, `ProductManifold`) is a runtime interface (not a template parameter: the optimizers are explicitly instantiated). No geometry (SO(3)/SE(3)) in the library. A model's `jacobian` is the derivative with respect to the step at zero, `active_param_dim` counts tangent dimensions, and an optimizer and its costs are all built from plain dimensions or all from the same manifold object (`addCost` checks it).

## Invariants to preserve
- **Bitwise determinism across thread counts**, run to run, for a given strategy and device. Nothing in the summation order may depend on the launch width, the scheduling or `threads`.
- **Euclidean == `EuclideanManifold` bitwise** (same arithmetic, no extra work in hot loops).
- **Linear-system cost == `computeCost(x)` bitwise** (both go through the same `robustifyChunk`/`robustifyElement` and the same partitions or groups); speculative LM relies on it.
- **One launch per evaluation** (`context.launches()`), none for zero elements.
- **TU-unique kernel names:** any kernel instantiated with a user type must carry `detail::CurrentTuId` in its name (`launchNamed`, `submitNamed`, `submitWithLocalMemory`, `single_task<Name>`). `__builtin_sycl_unique_stable_name` of a type does not include the per-TU prefix; `__builtin_sycl_unique_stable_id` of an internal-linkage variable does. Limit: the same file built twice with the same options in one executable.
- **No Eigen, virtual calls, exceptions, function pointers or `std::` math in library device code;** raw pointers, 32-bit atomics in the WorkGroup kernel.
- **Vecz:** the DPC++ native_cpu vectorizer crashes on the WorkGroup kernel when the group sums and the final reduction are inlined into it; `workGroupSums` and `workGroupFinalSums` are `[[gnu::noinline]]`: keep them out of line. The WorkGroup final reduction relies on device-scope barriers around an `acq_rel` counter increment by work-item 0 (comment in `WorkGroupKernel.hh`).
- Check changes with `Determinism*` and `compare_bench.py` against a build of the previous tree (analytical rows must match exactly; numerical rows to about 1e-9 across compilers). The existing tests run unmodified.
- WorkGroup is verified for correctness on native_cpu only and compiles device-only for spir64 and nvptx64 (libspirv/CUDA libdevice are missing here, so nvptx64 needs `-fno-sycl-libspirv -nocudalib --cuda-path=/nonexistent`); GPU performance is unverified.
- `SYCL_NATIVE_CPU_HOST_THREADS=1` makes the native_cpu runtime use a single thread.
