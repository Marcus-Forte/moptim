# Moptim

C++23 non-linear least-squares library (Gauss-Newton, Levenberg-Marquardt) on Eigen, on SYCL (DPC++ required). See `readme.md` for the math and dimension conventions.

## Build / test
- SYCL is a hard requirement: the build needs the DPC++ `clang++` (`-fsycl`) and fails at configure time otherwise. There is no non-SYCL build and no `WITH_SYCL` option. Eigen settings are in the "Eigen in the device pass" paragraph of `readme.md`: scalar Eigen in the device pass only (`EIGEN_DONT_VECTORIZE` through `-Xsycl-target-frontend=<triple>` in `CMakeLists.txt`, never in a header or as a global define), `EIGEN_MAX_STATIC_ALIGN_BYTES=16` on both passes, `-ffp-contract=fast`. Do not re-add a global `EIGEN_DONT_VECTORIZE` or `EIGEN_ARM64_USE_SVE`.
- Presets: `cmake --preset default` (DPC++ at `/opt/sycl`, Ninja, Release, `native_cpu`, `build/`) and `--preset sycl` (`native_cpu,nvptx64-nvidia-cuda,spir64`, `build_sycl/`, needs the CUDA and libspirv bitcode of the toolchain). Cache variables: `SYCL_TARGETS`, `MOPTIM_NATIVE_CPU_ARCH` (optional `-mcpu` of the `native_cpu` device code).
- The macOS host has no SYCL compiler. Build and run in the dev container (`C=$(docker ps -q --filter ancestor=mdnf1992/sycl-dev)`, repo at `/workspaces/moptim`, DPC++ at `/opt/sycl`, Eigen in `/usr/include/eigen3`, only the `native_cpu` device). Use a container-local build directory, never the repo's `build/`, `build_sycl/` or `build_sycl_cpu/` (one aliased Docker volume):
  `docker exec $C cmake -S /workspaces/moptim -B /root/moptim-builds/<name> -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=/opt/sycl/bin/clang -DCMAKE_CXX_COMPILER=/opt/sycl/bin/clang++`, then `docker exec $C cmake --build /root/moptim-builds/<name> -j 8` and `docker exec $C ctest --test-dir /root/moptim-builds/<name> --output-on-failure -j 4`.
- Tests: gtest (fetched by FetchContent at configure time, so it needs network). Test binary is `test_moptim`; run one test with `<build>/test/test_moptim --gtest_filter=Suite.Name`.
- Benchmarks: `<build>/test/bench_moptim [--threads N] [--strategy auto|chunked|workgroup] [name-substring]` (built with the tests, not run by ctest). It prints cost/`JTJ`/`JTb` checksums, so compare two builds for equivalence as well as speed (`test/compare_bench.py`). Timings on a loaded machine are noisy; compare minima over several interleaved runs. `test/bench_launch.cc` measures kernel launch latency; `test/spike/` is the standalone Phase 0 spike of the SYCL rewrite and is not part of the build.
- Only `-Wall` is set (no `-Werror`). `build/` and `build_sycl/` are gitignored.
- Optional flags: `-DUSE_CLANG_TIDY=ON` (does not work with SYCL; warns), `-DFORMAT_CODE=ON` (runs clang-format -i over all `.cc`/`.hh` on build).

## Layout
- `include/moptim/*.hh`: mostly header templates (costs, models, observer, result). Consumers include them as `"moptim/<Header>.hh"`, since `${CMAKE_CURRENT_SOURCE_DIR}/include` is the public include root. `src/` has `EigenSolver.cc`, `ExecutionContext.cc`, `GaussNewton.cc`, `LevenbergMarquardt.cc` and `NormalEquations.cc`; all but `ExecutionContext.cc` use explicit instantiation. Supporting a new scalar type means editing `src/*.cc`.
- CPU costs share `ChunkedCost.hh` (element chunking, weights/information/robust loss, accumulation); `AnalyticalCost` and `NumericalCost` only supply the Jacobian rows of a chunk. `NumericalCostForwardEuler`/`NumericalCostCentral` are aliases of `NumericalCost`. Public headers must stay valid C++20: mslam consumes them as a C++20 submodule.
- The costs still run host Eigen code (SYCL rewrite, Phase 1). `ExecutionContext.hh` (in-order queue, `threads`, `AssemblyStrategy`, launch counter, `detail::launch` through `nd_launch`) and `detail/` (`NormalEquationsKernel.hh`: Eigen-free, device-callable accumulation kernels, which `src/NormalEquations.cc` wraps; `Usm.hh`: USM RAII) are the kernel infrastructure. Device-callable code takes raw pointers, uses no Eigen, exceptions or virtuals, and calls math through helpers that work in a kernel (see `LossFunction.hh`: `std::sqrt`/`std::log` in a kernel make the DPC++ linker warn). Loss functions expose a `descriptor()` (`LossKind` + two numbers) so a kernel can run the built-ins through `detail::evaluateLoss()`.
- `test/`: gtest suites. New test files must be added to `test/CMakeLists.txt`. `test/nist/` holds the NIST StRD regression datasets. `test_device_*.cc` and `test_execution_context.cc` run kernels on the default SYCL device and compare them with the host.
- Library has no logging or timing. Telemetry goes through `IOptimizerObserver` (`Observer.hh`). Do not add `<iostream>`, `<format>` or logger dependencies (see `docs/logging.md`).
- `plan.md` and `improvements.md` are notes and reviews, not specs. They may be stale (`improvements.md` mentions removed `utils/`; `plan.md` items C1, C3, A1, C7 and C8 are implemented).
- `Manifold.hh` (`IManifold`, `EuclideanManifold`, `ProductManifold`) lets optimizers and costs work on parameters that are not a plain vector (`ambientDim()` = entries of `x`, `tangentDim()` = size of the linear system). Do not break these conventions:
  - The Euclidean path (constructors from `size_t` dimensions) must stay bit-identical to the pre-manifold behaviour: same arithmetic, no extra work in the hot loops. Check with `bench_moptim`'s notes column against a build of the previous tree, and run the existing tests unmodified.
  - It is a runtime interface, not a template parameter of the optimizers or costs: they are explicitly instantiated in `src/*.cc`.
  - No geometry in the library (no SO(3)/SE(3)): the storage and increment conventions belong to the consumer. Test and benchmark manifolds live in `test/manifold_models.hh`.
  - A model's `jacobian` is the derivative with respect to the step at zero, `active_param_dim` counts tangent dimensions, and an optimizer and its costs are built either all from plain dimensions or all from the same manifold object (`addCost` checks it).
